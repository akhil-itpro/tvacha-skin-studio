# Roadmap and acceptance gates

[Back to README](../README.md)

This separates working software from future validation and commercial work. It is not a promise of dates or outcomes.

## Implemented

- Quiz and optional photo flow, explicit uncertainty and useful fallbacks.
- Deterministic budget/sensitivity/shelf-aware recommendations and 24 real catalogue entries.
- Daily routine, owned-product shelf, comparisons, full paged history and weekly reminder.
- Guest/account data ownership, private opt-in photos, consent withdrawal, export and deletion.
- Founder aggregates, cap, product editor, support fields, referrals and waitlist join/leave.
- Face-free sharing, install metadata and generic offline behavior.
- Regression/HTTP suites, reproducible verification and portfolio documentation.

## Before a wider adult pilot

| Work | Acceptance evidence |
| --- | --- |
| Real-device behavior | Recorded Android/iPhone camera, upload, orientation, install and share checks |
| Model evaluation | A consented, non-public dataset/protocol; per-concern readability/error analysis across devices, lighting and people |
| Hosted authorization | Two independent real accounts; private photo, export, admin and deletion checks on the production gateway |
| Catalogue maintenance | Verified pack size, ingredients, cautions, links and dated prices; a maintenance owner |
| Operational readiness | Provider budget/limits, abuse controls, incident response and support/deletion procedure |
| Public launch review | Operator/grievance contact, privacy/terms/cosmetic wording and brand review |

## After evidence of repeat use

Consider better catalogue coverage, localization, clearer educational content and experiments that improve completion or routine follow-through. Each change should have a user problem, an observable success metric and a privacy/cost budget. Avoid adding models or steps simply to make the project appear more complex.

## Payments remain gated

The original brief proposes 300+ completed scans, 15% Day-7 return, 50+ waitlist responses with a price, payment-provider KYC and legal review before payment work. None is claimed as achieved here. If these gates are met and reviewed, a later payment implementation would require server-owned prices, verified idempotent webhooks, entitlement changes, cancellation and refund terms. No checkout, billing webhook or paid entitlement exists today.

## Explicit non-goals

Diagnosis, prescription advice, skin-color/attractiveness ranking, guaranteed cosmetic outcomes, invented details from unreadable images, fake social proof and paid product ranking are outside the product’s scope.
